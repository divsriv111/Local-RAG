# FastAPI Streaming LLM Endpoint - Implementation Guide

## Overview

This implementation provides a real-time streaming LLM endpoint using FastAPI with Server-Sent Events (SSE) for immediate token-by-token response delivery to clients.

## Endpoint Details

### POST `/api/llm/query`

Processes an LLM query with RAG pipeline and streams the response in real-time.

### Request Body

```python
class LLMQueryRequest(BaseModel):
    query: str                          # User query (1-5000 chars)
    workspace_id: str                   # Workspace ID for document context
    pdf_ids: List[str]                  # List of PDF IDs to search
    chat_history_id: str                # Chat history ID
    model_name: str                     # LLM model (e.g., "gpt-4-turbo")
    chat_history: List[Dict[str, str]]  # Previous messages (optional)
```

**Example:**

```json
{
  "query": "What are the main findings in the research paper?",
  "workspace_id": "123e4567-e89b-12d3-a456-426614174000",
  "pdf_ids": ["pdf-001", "pdf-002"],
  "chat_history_id": "chat-001",
  "model_name": "gpt-4-turbo",
  "chat_history": [
    { "role": "user", "content": "Hello" },
    { "role": "assistant", "content": "Hi! How can I help?" }
  ]
}
```

### Response Format

The endpoint returns a `StreamingResponse` with `text/event-stream` content type.

#### Headers

```
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive
X-Correlation-ID: <uuid>
X-Accel-Buffering: no
```

#### SSE Chunk Types

All chunks follow the Server-Sent Events format:

```
data: {json_object}\n\n
```

##### 1. Token Chunk

Sent for each token generated by the LLM.

```json
{
  "type": "token",
  "content": "word"
}
```

##### 2. Source Chunk

Sent for each relevant source document (sent before tokens).

```json
{
  "type": "source",
  "pdf": "research-paper.pdf",
  "page": 5,
  "relevance_score": 0.92
}
```

##### 3. Done Chunk

Sent at the end with complete response and metadata.

```json
{
  "type": "done",
  "answer": "Complete generated answer text...",
  "references": [{ "pdf": "file.pdf", "page": 5, "relevance_score": 0.92 }],
  "metadata": {
    "model_used": "gpt-4-turbo",
    "processing_time_ms": 2500.5,
    "token_count": 150
  }
}
```

##### 4. Error Chunk

Sent if an error occurs during processing.

```json
{
  "type": "error",
  "message": "An error occurred while generating the response: ..."
}
```

## Client Integration

### JavaScript/TypeScript (Angular)

#### Using EventSource (Simple)

```typescript
const eventSource = new EventSource("http://localhost:8000/api/llm/query");

eventSource.onmessage = (event) => {
  const chunk = JSON.parse(event.data);

  switch (chunk.type) {
    case "token":
      displayToken(chunk.content);
      break;
    case "source":
      addSourceReference(chunk.pdf, chunk.page);
      break;
    case "done":
      finishResponse(chunk.answer, chunk.references);
      eventSource.close();
      break;
    case "error":
      handleError(chunk.message);
      eventSource.close();
      break;
  }
};

eventSource.onerror = (error) => {
  console.error("EventSource error:", error);
  eventSource.close();
};
```

#### Using fetch with Streaming (Recommended for POST)

```typescript
async streamLLMQuery(request: LLMQueryRequest): Promise<void> {
  const response = await fetch('http://localhost:8000/api/llm/query', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Accept': 'text/event-stream'
    },
    body: JSON.stringify(request)
  });

  if (!response.ok) {
    throw new Error(`HTTP error! status: ${response.status}`);
  }

  const reader = response.body!.getReader();
  const decoder = new TextDecoder();

  while (true) {
    const { done, value } = await reader.read();

    if (done) break;

    // Decode chunk
    const text = decoder.decode(value, { stream: true });

    // Split by lines and process SSE format
    const lines = text.split('\n');

    for (const line of lines) {
      if (line.startsWith('data: ')) {
        const data = line.substring(6);

        try {
          const chunk = JSON.parse(data);

          switch (chunk.type) {
            case 'token':
              this.appendToken(chunk.content);
              break;
            case 'source':
              this.addSource(chunk.pdf, chunk.page);
              break;
            case 'done':
              this.finishResponse(chunk);
              return;
            case 'error':
              this.handleError(chunk.message);
              return;
          }
        } catch (e) {
          console.error('Failed to parse chunk:', e);
        }
      }
    }
  }
}
```

### Python Client

```python
import requests
import json

def stream_llm_query(request_data):
    url = "http://localhost:8000/api/llm/query"

    response = requests.post(
        url,
        json=request_data,
        headers={"Accept": "text/event-stream"},
        stream=True,
        timeout=300
    )

    for line in response.iter_lines():
        if line:
            line_str = line.decode('utf-8')

            if line_str.startswith("data: "):
                data_str = line_str[6:]
                chunk = json.loads(data_str)

                if chunk['type'] == 'token':
                    print(chunk['content'], end='', flush=True)
                elif chunk['type'] == 'done':
                    print("\n\nDone!")
                    break
                elif chunk['type'] == 'error':
                    print(f"\nError: {chunk['message']}")
                    break
```

## Performance Considerations

### Buffering

- Nginx buffering disabled via `X-Accel-Buffering: no` header
- Ensures immediate token delivery without delay
- Critical for real-time streaming experience

### Timeouts

- Default request timeout: 5 minutes (300 seconds)
- Configurable based on expected response time
- Long timeout needed for large document sets or complex queries

### Connection Management

- Uses HTTP keep-alive for persistent connections
- Properly closes connections on completion or error
- Tracks active connections for monitoring

### Memory Usage

- Streaming responses don't accumulate in memory
- Tokens yielded immediately and discarded
- Memory-efficient for long responses

## Troubleshooting

### Issue: No response received

**Causes:**

- RAG service not initialized
- Vector database not accessible
- No documents in vector store

**Solution:** Check logs for initialization errors and verify database connectivity.

### Issue: Streaming stops mid-response

**Causes:**

- LLM API timeout or rate limit
- Network interruption
- Memory issues

**Solution:** Check LLM service logs, verify API keys, increase timeout.

### Issue: Responses buffered (delayed)

**Causes:**

- Nginx buffering enabled
- Client not processing chunks immediately

**Solution:** Ensure `X-Accel-Buffering: no` header is set, verify client implementation.

### Issue: CORS errors from browser

**Causes:**

- Frontend origin not in `cors_origins` list
- Headers not properly exposed

**Solution:** Add frontend URL to `settings.cors_origins`, verify expose_headers configuration.

## Best Practices

1. **Always handle all chunk types** - Don't assume only tokens will be received
2. **Implement timeout handling** - Set reasonable timeouts (5+ minutes)
3. **Track correlation IDs** - Use for debugging and distributed tracing
4. **Buffer tokens client-side** - Display in real-time but keep full response
5. **Handle errors gracefully** - Show user-friendly error messages
6. **Close streams properly** - Clean up connections on completion/error
7. **Monitor performance** - Track response times and token counts in Elasticsearch
8. **Test with large documents** - Ensure timeouts and buffering work correctly

## Security Considerations

1. **Authentication** - Add JWT validation before processing queries
2. **Rate Limiting** - Implement per-user/workspace rate limits
3. **Input Validation** - Sanitize user queries and validate IDs
4. **Resource Limits** - Set max query length and PDF count
5. **CORS** - Only allow trusted frontend origins
6. **API Keys** - Secure storage of OpenAI/LLM API keys
7. **Logging** - Don't log sensitive data (queries may contain PII)
